# Design brief — Astronomy "moon" visual (for Claude on the web)

Paste everything below the line into claude.ai. It's self-contained. Goal: produce a
moon visual for the astronomy screen that actually **looks like a moon** and shows the
**correct phase**, suitable for an embedded LVGL/ThorVG display.

---

## Context

I'm building an ESP32‑P4 smart clock (ESP‑IDF v5.5, **LVGL 9.5**, 1024×600 MIPI‑DSI
display). One screen ("astronomy") shows the current moon phase, sunrise/sunset, and
aurora odds. The moon is currently a **flat grey‑filled circle** whose brightness is
just `illumination% × 2.55` — it does not read as a moon (no phase shape, no terminator,
no surface). I want to replace it.

### What data I have at render time
```c
typedef struct {
    float illumination_pct;   // 0.0–100.0  (0 = new, 100 = full)
    char  phase_name[20];     // "Waxing Crescent", "Full Moon", ...
    int   phase_index;        // 0–7  (0 new → 4 full → 7 waning crescent)
    int   days_to_full;
    int   days_to_new;
} moon_phase_t;
```
`phase_index` tells me **waxing vs waning** (0–4 waxing, 4–7 waning); `illumination_pct`
tells me how much of the disc is lit. So I can render any phase from these two.

### Rendering environment / constraints
- **Vector via ThorVG**: LVGL 9.5 embeds ThorVG, so it can play **Lottie (bodymovin)
  JSON** and render **SVG‑ish** vector paths into an ARGB8888 buffer (I allocate a
  ~200×200 or 300×300 px SPIRAM render buffer). No filesystem for fonts; assets live on
  an SD card at `A:/lottie/...`.
- **Small render target**: the moon widget is ~120–200 px square. Keep detail legible at
  that size.
- **Cheap to draw**: parsing a big Lottie holds the UI lock (~hundreds of ms), so smaller
  is better. A static/near‑static vector is fine — it does NOT need to animate.
- **Phase must be selectable**: I need to show *today's* phase, not cycle through all of
  them. Either (a) a data‑driven vector I can render per‑phase, or (b) a Lottie where I
  can seek/hold a specific frame that corresponds to a phase.

### What's wrong with my current generated asset
I have an existing `moon_cycle.json` Lottie (auto‑generated by a Python tool). Its
problems, which I want you to avoid/fix:
- The **terminator** (the light/dark boundary) is **wavy/polygonal**, not a smooth
  ellipse — it should be a clean elliptical arc that narrows the lit crescent as
  illumination drops.
- The **gibbous** frames have a visible **seam/notch** near the edge (bad path union).
- It's a **flat two‑tone** disc with no sense of a real moon (no soft shading, no maria/
  crater hints).

## What I want you to produce

1. **A short recommendation** on the best approach for this environment (Lottie JSON vs.
   a small parameterized vector I render per‑phase vs. a pre‑rendered PNG set per phase),
   with the trade‑offs for a 200 px ThorVG target. Be opinionated.

2. **The moon geometry, done correctly.** Explain (and give the math for) rendering a
   phase from `illumination_pct` + waxing/waning as the union/intersection of the disc
   circle and a **terminator ellipse** whose half‑width = `R × (1 − 2·illum_fraction)`
   (signed by waxing/waning), so:
   - new → fully dark, full → fully lit,
   - crescent/gibbous have a **smooth elliptical** terminator (no waviness, no seam).

3. **A real deliverable**, whichever the recommendation lands on:
   - If **Lottie**: a clean, minimal `moon.json` (or a small set) with a **smooth**
     terminator and a subtle moon look — soft limb shading and a few faint maria — that
     renders well at 200 px. Note any bodymovin features ThorVG may not support (masks,
     gradients, trim paths) and stay within a safe subset.
   - If **parameterized vector**: pseudocode/paths (arcs + ellipse) I can build with LVGL
     vector/canvas draw calls, taking `illumination_pct` and a `waxing` bool.
   - If **PNG set**: a plan for generating 8–16 phase PNGs (e.g., a small Python/Pillow or
     SVG script) with proper terminator + light shading, plus how I'd pick by phase.

4. **Aesthetic**: a soft, slightly warm‑grey lit surface with a faint hint of maria and a
   gentle limb darkening — not a flat white disc, not photorealistic. Unlit portion very
   dark (near the panel background), maybe a faint earthshine rim on thin crescents.

Prefer the **simple, robust** option that looks good at small size over anything clever.
Give me copy‑pasteable output (JSON or code) plus the reasoning.
